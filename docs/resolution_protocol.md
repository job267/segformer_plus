# E4 分辨率实验协议

冻结日期：2026-10-18，正式运行前记录。用户已同意先做 E4，再依据验证结果决定后续 E5。E0–E3 的原始代码、配置、指标和权重保持不变。

对照为 E3_combined，第 48 轮最佳验证权重；Val mIoU=71.001310%，Test mIoU=61.421587%。E4 独立设置 seed=42，从同一固定 ImageNet MiT-B0 编码器和新建 11 类头开始，不使用 E3 微调状态。

| 项目 | E3 | E4 |
|---|---|---|
| 输入/训练标签网格 | 384×384 | 512×512 |
| 验证/测试标签网格 | 384×384 | 384×384 |
| 增强 | 同步水平翻转 + 轻量颜色增强 | 相同 |
| 损失 | CE + 0.5 Dice | 相同 |
| 初始化、数据、种子 | 原固定版本，seed=42 | 相同 |
| 优化器与预算 | AdamW，lr=6e-5，wd=0.01，batch=4，50 轮，CUDA AMP | 相同 |

标签从原始索引 mask 直接最近邻缩放，避免 512→384 的二次重采样。验证/测试输入为 512×512，但 FP32 logits 在 loss 和 argmax 前统一插值到 384×384，align_corners=False；保持整个划分累计混淆矩阵、ignore=255 和 11 类定义。训练标签随训练网格为 512×512，因此训练损失不与 E3 数值直接比较。此实验改变整套训练与推理分辨率，不能单独区分两者贡献。

每轮按共同标签网格计算 Val mIoU，最高值选模型。全部 50 轮之后对该权重执行一次最终测试；中断恢复复用同一权重已完成的测试结果。训练前核验 E3 全部原有源文件哈希、权重 SHA256 和数据审计；逐轮保留完整 checkpoint、CSV、状态和最佳权重，使用系统运行锁，不覆盖历史目录。

E4 独立保存 results/resolution_comparison.csv、resolution_per_class.csv 与 reports/resolution_ablation.md。只按 Val mIoU 选择 E3/E4，验证同分保留 E3，不按 Test 改选；任何正负变化均如实记录。当前只有单 seed，测试集已查看过，因此不宣称稳定性、统计显著性或新增未见盲测性能。预算保持相同轮数与 batch，计算量随像素数增加，应同时报告训练时间与峰值显存。

预先门槛：40 项核心测试通过；真实预训练模型在 batch=4、512×512 完成前向/反向/更新；101 张验证与 233 张测试标签同 E3 逐像素一致，且类别像素总数同原 E3 归档；真实 512 输入/384 标签的 FP32 验证批次通过。诊断不计入正式轮次，不运行测试模型推理。

本次先执行 E4。加权 CE 的 E5、多随机种子、长预算和新架构均未自动排入队列，待 E4 验证结果后决定。模型推理演示、FP32/FP16 效率测试仍为后续交付内容。

# E4/E5 多随机种子复核协议

冻结日期：2026-10-18，正式新增训练前记录。用户同意对 E4/E5 补充多种子对照，检验原 seed=42 的小幅差异是否在其他随机初始化/训练顺序下仍然出现。不引入新超参数、损失、数据、预算或模型。

固定种子 `[42,2024,3407]`，每个种子均运行 E4、E5。seed=42 复用已完整归档的 E4_resolution、E5_weighted，不重训、不重复测试。新增顺序固定为：

1. E4_seed2024，50 轮。
2. E5_seed2024，50 轮。
3. E4_seed3407，50 轮。
4. E5_seed3407，50 轮。

每组除 seed、实验 ID 与独立输出目录外，与原方案配置完全相同：512×512 输入/训练标签，384×384 验证/测试标签，batch=4、AdamW lr=6e-5、wd=0.01、50 轮、固定学习率、CUDA AMP，相同增强与固定版本数据。E4 使用原 CE+0.5 Dice 引擎，E5 使用已核验的原加权引擎和已冻结训练频率权重。原 E0–E5 所有源文件、配置和归档均不修改。

每次单独设置 Python/NumPy/Torch/CUDA 种子，构造同一固定 ImageNet MiT-B0 编码器和新建 11 类头，不能接续其他训练权重。CPU 预检和实际训练均对全部初始参数/buffers 计算 SHA256，同一种子下 E4/E5 必须逐位一致；两个新增种子的完整初始化哈希应不同。数据加载器均使用各自相同种子的独立 Generator；初始哈希检查不消耗 RNG。现有 CUDA 非确定性限制仍然适用，不承诺完整训练逐位确定。

每轮按最高 Val mIoU 选权重，固定 50 轮之后执行一次完整最终测试并记录 journal；归档恢复复用同一权重的已完成测试。所有验证/测试均用同一 384×384 标签网格，整划分混淆矩阵、ignore=255、11 类口径不变。逐组核验 50 行历史、最佳验证轮次、权重文件、原有代码/数据哈希、预检身份、初始模型哈希与类别像素数。

队列及每组训练均持有系统文件锁；错误即停止后续训练，保留诊断；`--resume` 跳过经过核验的已完成组，恢复未完成组。预检和队列计划冻结源码清单；队列运行期间不编辑 src/、scripts/、configs/ 或 requirements.txt。运行记录和文档可更新。

统计使用三个种子各自的最佳验证模型结果。每组报告 Val/Test mIoU 与测试像素准确率的均值及样本标准差（ddof=1），并报告每个种子的 E5−E4 差值及差值均值/std。中途仅纳入两组都完整完成的同种子，防止不等样本数比较；仅一对时标准差写空，不写零。Val/Test 全 11 类也报告相同完整配对种子的均值/std。

全部三对完成后按平均最佳 Val mIoU 选择 E4/E5，精确同分保留 E4，不按 Test 选择方案。部署代表预先固定为胜出方案已有 seed=42 的最佳模型，不按测试或验证挑选其他种子，不集成，不覆盖原单种子选择记录。最终结果为 results/multiseed/selection.json，报告为 reports/multiseed.md。

三种子只能提供描述性复核，不宣称统计显著性或总体效果的置信区间；同一测试集的场景抽样不确定性不由 seed std 表示。测试集已查看，不能当作未见盲测。不自动追加种子、长预算或新网络，待本轮完整结果再决定后续。
